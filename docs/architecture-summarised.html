Architecture · Study map

Chord Sheets, end to end

A local-first React app in the browser, one Cloud Function behind it, and the external chord sites, Gemini, and Firestore it depends on. Follow the arrows to see where each request goes and where the two halves meet.

01 · Frontend

The browser does the work

  • src/pages owns route flows: Home, Search, Session, Share import, Lyrics view, Privacy.
  • src/components renders the sheet, modals, import UI, transpose and display controls.
  • src/lib is framework-free logic: transposition, chord editing, layout, storage, API calls, pads, analytics.
  • Local-first: sessions, songs and preferences live in IndexedDB via idb-keyval. There is no account or server session.
  • Google Analytics is optional: production only, and visitors can turn it off on the Privacy page.

02 · Backend

One function, many routes

  • A single onRequest function dispatches by path. It runs at us-central1, capped at 3 instances, concurrency 5, 512 MiB, 300 s.
  • /scrape and /simplify load source charts; /search streams partial results as NDJSON.
  • Search fans out to three adapters in parallel and caches complete results for five minutes; a failed site is reported without hiding the others.
  • /share and /lyrics-share publish to Firestore; /extract-sheet runs PDF or Gemini extraction.

03 · Data

Firestore is the shared store

  • Firestore holds sharedSets, sharedLyrics, source-chart caches, aliases and search results.
  • Firestore rules deny every browser read and write. Only the Admin SDK inside the function touches it.
  • Caches are short-lived — charts six hours, search five minutes — while share links live for seven days.
  • The lyrics publication ID is derived from a secret held by the publishing browser.

04 · Follow one import

From pasted link to saved song

  1. Paste a URL or pick a search result. The browser sends only the source URL.
  2. Backend checkUrl enforces HTTPS, the four-domain allow-list and no credentials or custom ports.
  3. loadSourceChart checks the Firestore chart cache, then calls scrapeUrls with two workers and a per-host gate.
  4. safeFetch resolves DNS, blocks private IPs, applies timeouts and size limits. The matching adapter parses the page.
  5. The normalizer builds sections, the key detector infers the key, simplification runs, and the browser caches the song in IndexedDB.

05 · Build & deploy

Two compilers, one deploy

  • tsc -b && vite build produces dist/; the functions package compiles separately to lib/ on Node 22.
  • Production sheet extraction bypasses the Hosting rewrite and calls the function URL directly, because Hosting ends rewritten requests at 60 seconds.
  • Locally, Vite proxies /api to the Functions emulator under the demo-chords project.
  • GitHub Actions lints, tests, builds both halves, then deploys Hosting, Functions and Firestore rules from main.
  • GEMINI_API_KEY is a function secret; VITE_FIREBASE_* values are public browser identifiers.
